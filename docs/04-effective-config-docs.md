# 配置生效机制与智能字段速查

当你在提供商里设了一个 BaseURL，又在模型里单独配置了一个参数，发送请求时到底听谁的？

为了让你在管理几十个渠道和模型时不再抓瞎，我们设计了明确的**有效配置推导规则**，并在界面里内置了随时可查的**字段速查抽屉 (DocsDrawer)**。

---

## 参数是如何生效的？

整个系统的继承规则非常简单直观，按优先级从高到低分为三层：

```
1. 模型局部覆盖 (最高优先级)
   如果你在某个具体模型里单独设置了参数（比如特定的 maxTokens），它会优先于一切。
          ↓ (如果模型没有单独设置)
2. 提供商全局配置 (中等优先级)
   自动继承你在这个渠道顶层配置的信息（比如 BaseURL、API Key）。
          ↓ (如果渠道也未配置)
3. 系统内置缺省 (保底机制)
   使用协议的标准默认行为（比如默认温度 0.7、默认无特定补丁）。
```

### 这种设计带来的好处
- **不用重复填**：在一个提供商下添加 20 个模型，只需要把 API Key 和 BaseURL 配一次，所有模型自动生效。
- **改特例很方便**：遇到某个需要单独设置长上下文或特殊采样温度的模型，直接去那个模型的抽屉里改一下，完全不会干扰其他模型。

---

## 随时查看真实生效值：智能字段抽屉

在编辑抽屉里，每一个配置项旁边都有一个灰色的 `?` 图标。点击它，右侧就会滑出该字段的详细速查说明：

![字段速查抽屉](./images/06-docs-drawer.png)

### 抽屉里能看到什么？

1. **当前模型真实生效值**：
   系统会基于上面的三层规则实时计算，并直接把发往上游的最终数值展示在最上方。
2. **来源依据徽章**：
   清楚标明这个值是从哪里来的（比如显示绿色徽章 **「继承自提供商」**、紫色徽章 **「模型主键」** 或蓝色徽章 **「系统默认」**），并在下方附上一句话依据说明。
3. **字段概述与技术细节**：
   告诉你这个字段在通信协议里的原始参数名叫什么，上游网关会怎样处理它。
4. **常见取值与配置示例**：
   提供真实可行的填法范例，避免格式错误。
5. **适用场景与排错提示**：
   告诉你遇到什么报错（例如 404 或 400）时需要调整这个字段，改完能解决什么问题。

有了这个抽屉，你不需要频繁翻阅各家服务商繁杂的 API 文档，配置时心里始终有数。
