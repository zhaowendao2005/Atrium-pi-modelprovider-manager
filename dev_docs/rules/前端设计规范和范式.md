# 前端设计规范与架构范式 (Frontend Architecture & Design Standards)

本文档为 **Pi Model Provider Manager** 项目前端开发的强制性设计规范与架构范式。所有涉及 UI 界面、状态管理、组件拆分、持久化及交互逻辑的开发均必须严格遵循本规范。

---

## 一、 核心设计理念 (iOS 风格与视觉规范)

1. **整体视觉风格**：
   - 遵循 Apple / iOS 现代极简设计美学：大圆角（`rounded-2xl`、`rounded-xl`）、精细微边框（`border-slate-200/80 dark:border-slate-800/80`）、层级分明的阴影与毛玻璃模糊效果（`backdrop-blur-md`）。
   - 视觉色彩采用低饱和度、高对比度的现代灰色调与精致的强调色（如 iOS 经典蓝、紫与石墨灰）。

2. **图标与视觉符号规范**：
   - **严格禁止使用任何 Emoji**（如 🧠, 🖼️, 🚀 等表情符号）。
   - **所有图标一律采用精细矢量 SVG 图标**（推荐基于 `lucide-vue-next` 或内联标准 SVG 路径），线宽统一为 `1.5px` 或 `1.75px`，保持精致轻量。

3. **自定义苹果风格滚动条 (`AppleScrollArea`)**：
   - 彻底隐藏各操作系统原生的粗糙滚动条。
   - 所有可滚动区域统一使用 `AppleScrollArea` 组件封装。
   - 滚动条滑块（Thumb）呈细圆角胶囊状，默认半透明弱化，鼠标悬停或内容滚动时渐变淡入，停止交互后平滑淡出。
   - 同时支持纵向（Vertical）与横向（Horizontal）平滑自适应滚动。

---

## 二、 布局与导航架构 (Layout & Navigation)

1. **可伸缩左侧边栏 (Collapsible Sidebar)**：
   - **展开状态**：宽度约 `220px ~ 240px`，展示分类图标、文字标题、活跃指示器与数据统计徽标。
   - **折叠状态**：宽度收缩为 `64px`，平滑隐藏文本，仅保留精致居中的 SVG 图标按钮，并配备 Tooltip 悬浮提示。
   - **上下分区对齐**：
     - **顶部区**：主功能导航（提供商与模型管理）。
     - **底部区**：全局系统设置（Settings）及版本信息，**强制向下对齐（Bottom-aligned）**。

2. **主内容分区 (Content Area)**：
   - 高度撑满窗口剩余空间（`h-full flex-1 overflow-hidden`），与侧边栏高度完全联动。
   - 内部各个视图板块拥有独立的局部滚动容器，防止整页抖动。

---

## 三、 全局状态管理规范 (Pinia State Management)

1. **禁止滥用本地 `ref`**：
   - **严禁在顶层组件间、跨页面通信或持久化业务实体中滥用 Vue 本地 `ref` / `reactive`**。
   - 所有的业务数据（提供商列表、模型定义、当前选中项、连接状态）、配置持久化及全局窗口交互状态，**必须统一收敛到 Pinia Store 中**。

2. **Store 目录层级划分**：
   - `src/stores/`（业务数据层）：
     - `provider.ts`：负责 Provider 与 Model 的全量状态、CRUD、分组算法、过滤搜索、远程连接测试等。
     - `settings.ts`：负责用户偏好、YAML 存储路径、追踪开关等全局配置。
   - `src/stores/windows/`（窗口与交互状态层）：
     - `navigation.ts`：负责侧边栏折叠/展开、当前活动视图标签。
     - `drawer.ts`：负责抽屉组件的开闭状态、当前编辑对象与表单上下文。
     - `window.ts`：负责跨平台桌面窗口控制（最小化、最大化、关闭、标题栏拖拽）。

## 四、 组件与页面边界划分 (Components vs Views)

严格遵循清晰的职责分层，防止组件库膨胀与代码散乱：

```
src/
├── components/          # 【高复用通用组件库】
│   └── ui/              # 跨项目/跨页面通用（如 AppleScrollArea, Button, Input, Select, Sheet, Switch, Badge）
│
└── views/               # 【页面级视图】(依路由和 DOM Tree 组织，通常 3-4 层深度)
    ├── layout/          # 框架级布局 (MainLayout, Sidebar, Titlebar)
    ├── providers/       # 提供商管理主视图 (ProvidersView)
    │   └── components/  # 仅当前视图专属使用的子组件 (ProviderSidebarList, ModelFamilyGroup, ModelCard, ProviderDrawer, ModelDrawer)
    └── settings/        # 设置视图 (SettingsView)
```

1. **`components/ui/` 的判定标准**：
   - 必须具备**高复用性**（在 2 个或以上无关业务页面中使用），且**不绑定具体业务模型字段**（如不直接依赖 `ProviderSchema`）。
2. **`views/<page>/components/` 的判定标准**：
   - 仅供特定业务视图使用的专用 UI 片段（如模型卡片、抽屉表单），必须就近放置在该 view 的 `components/` 子目录下，严禁污染全局通用组件库。

---

## 五、 数据持久化规范 (YAML Storage)

1. **数据格式**：全量配置采用标准 **YAML** 格式存储。
2. **默认存储路径**：
   - 统一存放在 Pi 配置目录与 Agent 平级的目录：`~/.pi/pi-modelprovider-manager-data/config.yaml`（Windows 下对应 `C:\Users\<username>\.pi\pi-modelprovider-manager-data\config.yaml`）。
3. **数据一致性保证**：
   - 前端管理面板对任何 Provider 或 Model 的增删改查均自动同步回写至该 YAML 文件。
   - Pi Agent Extension 运行时在启动阶段直接从该 YAML 文件读取配置，向 Pi 内核注入提供商与模型。
